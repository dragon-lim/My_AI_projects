## Agent 추가 

# 제안 1 ) 
원문 검색으로 대조하여
llm이 완성한 필기노트를 
Agent가 검사하고 처리를 결정
(근거 없는 문장을 어떻게 처리할지만 결정)

Agent 결정은 통과 / 확인 필요 / 삭제
그리고 애매한 부분은
"확인 필요"로 표시해 학생에게 판단을 넘긴다

검증 단계에서는 LLM을 쓰지 않는다
(자기가 만든 노트이기 때문에)

"이 한 문장이 원문 어딘가에 있는가"를 묻는 작업


원문 txt 파일과 llm이 완성한 노트를 비교하여
할루시네이션 방지 및 더욱 정확한 정보


결과

무엇을
LLM이 만든 노트 ↔ 전사 원문 txt 를 문장 단위로 대조

어떻게
"이 문장이 원문 어딘가에 있는가"를 의미 기반 검색으로 확인
→ 검증에는 LLM을 쓰지 않음 (자기 검토는 신뢰할 수 없으므로 외부 원문과 대조)

Agent가 하는 일
문장을 다시 쓰지 않고, 처리만 결정 → 통과 / 확인 필요(학생에게) / 삭제

효과
강의에 없던 내용이 노트에 남지 않음 = 할루시네이션 방지



# 제안 2)

항목이 쌓이고, 학생은 부담을 느껴 사용이 꺼려질 수 있다

구글 캘린더 — 복습 예정 시각에 다른 일정이 있었는지. 학교 시간표, 아르바이트, 개인 약속 등. 일정의 시간대 확인

과거 복습 일자의 요일 시간 정보등을 바탕으로 사용자가 명확히 복습에 참여할 수 있는 계획표를 세워준다

(매주 금요일은 아르바이트 때문에 복습을 빠졌다 - 금요일은 복습 계획을 생성하지 않는다 or 복습 일정을 간단하게 짧은 복습으로 잡는다)



금요일 저녁마다 캘린더에 일정 있음	
시간 충돌 -> 토요일 오전으로 이동
캘린더는 비었는데 안 함	
주말 앞 피로	-> 금요일은 짧게
했는데 시간이 2배 걸림	
개념이 어려움 -> 선행 개념 질문부터 다시
캘린더도 비고 분량도 적은데 안 함	
원인 불명 -> 학생에게 잡도리

1.과거 이행 기록 + 캘린더 시간대를 조사한다
2.여러 원인 중 무엇인지 추정한다 (단정 X)
3.원인에 맞는 대응을 고른다 (이동 / 축소 / 선행 / 질문)
4.바뀐 계획을 캘린더에 반영한다
5.다음 주에 다시 관찰한다 → 안 나아지면 다른 원인으로 재판단
